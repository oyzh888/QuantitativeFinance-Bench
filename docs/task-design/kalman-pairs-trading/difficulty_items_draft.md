## DI-01: Kalman Filter Dynamic Hedge Ratio — **HARD**

**Core idea:** 2D state `x=[alpha, beta]` evolving as random walk. Observation: `price_A[t] = [1, price_B[t]] @ x[t] + noise`.

**Key formula:**
```
Q = (1e-4 / (1 - 1e-4)) * I_2   # delta-parameterization
R = var(diff(price_A[:30]))       # empirical
P_0 = 1e6 * I_2                  # vague prior
```

**Top traps for LLMs:**
1. **Matrix shapes** — H must be (1,2) row vector, not (2,1). Wrong shape → S is (2,2) not scalar
2. **Q/R calibration** — LLMs hardcode Q=I or Q=0 (too certain), ignoring delta-parameterization
3. **Forgetting alpha** — model only beta (1D state), causing drift-biased spread
4. **Using pykalman** — EM parameter estimation overfits; shapes mismatched

**Oracle:** manual numpy predict/update loop, no library shortcuts allowed

## DI-02: OU Half-Life Entry Threshold — **HARD**

**Core idea:** Regress `Δs` on `s[t-1]` → `kappa = -slope` (must be > 0) → `half_life = log(2)/kappa` → threshold = f(half_life)

**Key traps:**
1. **Sign error** — `b` from OLS is negative for mean-reverting; `kappa = -b`. LLMs set `kappa = b` → negative half-life
2. **dt confusion** — kappa is in units/day; annualizing before computing half-life yields years not days
3. **Non-stationary edge case** — if `kappa <= 0`, suppress trading (code crashes otherwise)
4. **Flat threshold** — LLMs hardcode threshold=2.0 ignoring the half-life dependency

## DI-03: Transaction Costs — **MEDIUM**

Primary trap: **bps conversion** — 0.1 bps = 0.00001 (not 0.001 or 0.0001). 10x errors in slippage.  
Also: 4 transactions per round-trip (2 legs × entry + exit), not 2.

## DI-04: Rolling Cointegration Regime Detection — **HARD**

**4-state FSM:**
```
COINTEGRATED → BREAKDOWN_WATCH(n) → BROKEN → RECOVERY_WATCH(n) → COINTEGRATED
```

**Key rules:**
- Breakdown: 5 **consecutive** days p>0.10 (counter resets on any good day)
- Recovery: 3 **consecutive** days p<0.05
- Close positions immediately on entering BROKEN
- No new entries during WATCH states

**Top traps:**
1. `coint()` returns `(stat, pvalue, crits)` — use index [1], not [0]
2. `sum()` instead of consecutive counter → allows non-consecutive days
3. Missing RECOVERY_WATCH state → re-enters immediately after 1 good day
4. First 59 days burn-in not handled → trades on partial window

---

## DI-05: Multi-Pair Correlation Constraint — **HARD**

**Rule:** rolling 60-day corr of z-scores; if `|corr[i,j]| > 0.7` → multiply BOTH positions by 0.5 (floor, not cumulative).

**Primary trap:** applying reduction multiplicatively (`0.5 * 0.5 = 0.25`) instead of flooring at `min(current, 0.5)`.
